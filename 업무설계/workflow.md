# Workflow

## 1. 실행 순서

| 순서 | Task | 실행 주체 | 적용 패턴 |
|---|---|---|---|
| 1 | lot·wafer·value 붙여넣기와 good/bad 구분 입력 | 사람 | - |
| 2 | 입력값 정리(형식 확인, 중복·결측 제거)와 설비 진행 이력 조회·lot·wafer 기준 결합 | 코드 | - |
| 3 | 스텝별 order·unit 조합 생성과 bad wafer가 유의하게 몰린 불량 조합 판정 | 코드 | Router 분기 지점 |
| 4 | 불량 조합 unit의 FDC 데이터 조회와 파라미터별 유의차 계산(bad 경로 wafer vs 같은 unit의 나머지 wafer) | 코드 | - |
| 5 | 유의차가 큰 FDC 파라미터의 의미 해석과 원인 가설 도출 | AI | Parallel ③ |
| 6 | 차트와 원인 가설·확인 항목을 정리한 분석 보고서 작성 | AI | Gen / Eval (Generator) |
| 6-1 | 분석 보고서 검토 (PASS / FAIL 판정) | AI | Gen / Eval (Evaluator) |
| 7 | 원인 확정과 조치 결정(unit 점검, 경로 회피) | 사람 | - |

## 2. 적용 패턴

### Parallel

| 대상 Task | 유형 | 병렬 실행 작업 |
|---|---|---|
| 5. FDC 파라미터 의미 해석과 원인 가설 도출 | ③ 다른 입력 × 같은 에이전트 | 불량 조합마다 해당 조합의 FDC 유의차 결과를 같은 역할의 해석 Agent가 각각 독립적으로 해석 |

### Router

| 분기 지점 | 분기 조건 | 조건별 다음 Task |
|---|---|---|
| 3. 불량 조합 판정 결과 | 상태: 불량 조합 1건 이상 / 0건 | 1건 이상 → 4. FDC 유의차 계산 → 5. FDC 해석(Parallel) → 6. 보고서 작성 / 0건 → 4·5를 건너뛰고 6. 보고서 작성("불량 조합 없음" 결과) |

### Gen / Eval

| 항목 | 내용 |
|---|---|
| 대상 Task | 6. 분석 보고서 작성 |
| Generator | 보고서 작성 AI (Task 6) |
| Evaluator | 보고서 검토 AI (Task 6-1) — 기준에 따라 PASS / FAIL과 문제점만 전달하고 직접 수정하지 않음 |
| 검토 기준 | ① 결과물 구성 5개(분석 요약 · 조합 funnel · 불량 조합별 상세 · FDC 유의차 · 원인 가설과 확인 요청 사항)가 모두 있음 (불량 조합 0건이면 분석 요약 · 조합 funnel · "불량 조합 없음" 표시) ② 원인 가설이 FDC 유의차 수치와 맞음 ③ 원인 가설에 확정 표현이 없음 ④ 차트 중심, 설명 문장 최소화 |
| PASS | 모든 기준 충족 → 7. 사람 |
| FAIL 시 돌아갈 Task | 가설·수치 불일치 → 5. 해당 조합의 FDC 해석 AI 재실행 후 6. 보고서 수정 / 구성·표현 문제 → 6. 보고서 작성 AI 수정 |
| 최대 반복 | 1회 — 수정 후 재검토에서도 FAIL이면 검토 의견과 함께 7. 사람에게 넘김 |

## 3. Task 간 연결 관계

- 1 → 2: 붙여넣은 lot·wafer·value와 good/bad 구분
- 2 → 3: 설비 진행 이력이 결합된 wafer 데이터
- 3 → Router: 판정된 불량 조합 목록
- Router(1건 이상) → 4: 불량 조합 목록
- 4 → 5: 불량 조합별 FDC 유의차 결과 (조합마다 병렬 해석으로 분배)
- 5 → 6: 불량 조합별 원인 가설 (모든 조합의 해석이 끝난 뒤 취합)
- Router(0건) → 6: 불량 조합 없음 결과
- 3·4 → 6: 조합 분석·FDC 유의차 결과와 차트 데이터
- 6 → 6-1: 분석 보고서 초안
- 6-1(PASS) → 7: 분석 보고서
- 6-1(FAIL, 가설·수치 불일치) → 5 → 6 → 6-1: 해당 조합 재해석 후 보고서 수정·재검토 (최대 1회)
- 6-1(FAIL, 구성·표현 문제) → 6 → 6-1: 보고서 수정·재검토 (최대 1회)
- 6-1(재검토 FAIL) → 7: 보고서와 검토 의견

## 4. Workflow 시각화

```
[사람: lot·wafer·value 붙여넣기와 good/bad 구분 입력]
                    ↓
[코드: 입력값 정리 + 설비 진행 이력 결합]
                    ↓
[코드: order·unit 조합 생성 + 불량 조합 판정]
                    ↓
        불량 조합 1건 이상 / 0건        ← Router (상태)
          ↙                    ↘
[코드: FDC 유의차 계산]            │
          ↓                        │
   ┌──────┼──────┐                 │
   ↓      ↓      ↓                 │  ← Parallel ③
[AI: 조합1][AI: 조합2][AI: 조합N]      │
 해석     해석     해석                │
   └──────┼──────┘                 │
          ↓                        ↓
[AI: 분석 보고서 작성]  ←──────────────┘   ← Generator
          ↓
[AI: 보고서 검토]                          ← Evaluator
          ↓
     ┌────┴─────┐
    PASS       FAIL (최대 1회 수정)
     ↓          ├─ 가설·수치 불일치 → [AI: 해당 조합 해석] 재실행 → 보고서 수정 → 재검토
     ↓          └─ 구성·표현 문제   → [AI: 보고서 작성] 수정 → 재검토
     ↓               (재검토도 FAIL이면 → 검토 의견과 함께 사람에게)
[사람: 원인 확정과 조치 결정]
```
