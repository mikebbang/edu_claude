# UNIT_COMMONALITY (웹)

설비 이력에서 bad를 끌어올린 설비 · 챔버 경로(공정 유닛 조합)를 찾아, funnel 차트와 혐의 대상 순위표로 보여 주는 웹 화면입니다. 사내 서버에 띄우고 브라우저로 접속해 씁니다(기본 포트 3002, 로그인 없음). 데이터는 **Job ID**로 DB에서 바로 가져오거나, 예전처럼 **raw.csv**를 올려서 넣습니다.

판정 계산은 `main` 브랜치의 `notebooks/real_data_funnel.ipynb`(커밋 `699e381`)와 같은 결과를 냅니다. 같은 raw.csv와 같은 설정이면 조합, z, 기준선, 판정, 혐의 대상 순위가 모두 같습니다.

## 구성

| 경로 | 내용 |
|---|---|
| `combi/` | 계산 엔진: CSV 읽기 · Value 치우침과 part 맞춤 · 조합 판정 · 혐의 대상 순위 · 화면에 보낼 값. `db.py`는 Job ID로 DB에서 raw.csv 만들기 |
| `web/app.py` | 웹 서버: 파일 올리기 · 실행(따로 프로세스에서 여러 개 동시에) · 실행 기록 · 결과 · 상세 · 비교 API |
| `web/worker.py` | 판정 한 번을 계산하는 프로세스: 결과를 `data/runs/<실행 id>/`에 저장 |
| `web/static/` | 화면 (HTML · CSS · JS, 외부 라이브러리나 인터넷 연결 없이 동작). `guide.html`은 화면 안의 사용자 가이드, `fonts/`는 로고 글꼴(Poppins ExtraBold · `OFL.txt` 라이선스) |
| `requirements.txt` | 설치할 패키지 (버전 고정) |
| `demo_raw.csv` | 시험용 가상 데이터 |

## 실행 가이드 (RHEL 9 · Python 3.12)

### 1. 코드 받기

git이 있으면:

```bash
git clone -b funnel-web --single-branch https://github.com/mikebbang/edu_claude.git funnel-web
```

서버가 GitHub에 접속할 수 없으면(폐쇄망) PC에서 아래 ZIP을 받아 서버로 옮긴 뒤 풉니다.

```bash
unzip edu_claude-funnel-web.zip && mv edu_claude-funnel-web funnel-web
```

ZIP 주소: `https://github.com/mikebbang/edu_claude/archive/refs/heads/funnel-web.zip`

### 2. 가상환경(venv) 만들고 패키지 설치

```bash
cd funnel-web
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

- `python3.12`가 없다는 오류가 나면 `python3 --version`으로 3.12인지 확인하고 `python3 -m venv .venv`를 씁니다.
- 사내 PyPI 미러를 쓰는 서버라면 평소 pip 설정 그대로 설치됩니다. DB 조회용 `connectorx` · `polars` · `pyarrow`도 함께 설치됩니다.
- 예전 버전을 쓰던 폴더라면 코드를 받은 뒤 `pip install -r requirements.txt`를 한 번 더 실행합니다.

### 2-1. DB 연결 (Job ID로 가져오기)

DB 접속 주소에는 비밀번호가 들어 있어서 코드나 GitHub(공개 저장소)에는 넣지 않습니다. 서버의 프로젝트 폴더에 `.env` 파일을 만들어 넣습니다(`.gitignore`에 있어 git에 올라가지 않음).

```bash
cat > .env <<'EOF'
COMBI_DB_URL=postgresql://<사용자>:<비밀번호>@<DB 주소>:5432/occas
EOF
chmod 600 .env
```

- 노트북에서 쓰던 `cx.read_sql("postgresql://…", …)`의 접속 주소를 그대로 넣으면 됩니다. 비밀번호에 `!` 같은 글자가 있어도 `.env`에는 그대로 씁니다.
- 읽는 표는 `occas.tmp_fab_ept_table_tg`입니다. 다른 표를 쓰려면 `.env`에 `COMBI_DB_TABLE=스키마.표이름`을 더합니다.
- 서버를 다시 켜야 적용됩니다. `.env`가 없으면 Job ID 기능만 꺼지고 raw.csv 올리기는 그대로 됩니다.

### 3. 서버 실행

```bash
python -m web
```

`Uvicorn running on http://0.0.0.0:3002`가 나오면 브라우저에서 `http://<서버 주소>:3002`로 접속합니다. 끄려면 `Ctrl+C`를 누릅니다.

### 4. 터미널을 닫아도 계속 띄우기

```bash
nohup .venv/bin/python -m web > web.log 2>&1 &
```

- 끌 때: `pkill -f "python -m web"`
- 로그 보기: `tail -f web.log`

서버가 다시 켜질 때 자동으로 띄우려면 systemd 서비스로 등록합니다(관리자 권한 필요). `/etc/systemd/system/combi-web.service`:

```ini
[Unit]
Description=UNIT_COMMONALITY 웹
After=network.target

[Service]
User=<실행할 계정>
WorkingDirectory=/<설치 경로>/funnel-web
Environment=COMBI_WORKERS=4
ExecStart=/<설치 경로>/funnel-web/.venv/bin/python -m web
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now combi-web
```

### 5. 다른 PC에서 접속이 안 되면 (방화벽)

```bash
sudo firewall-cmd --permanent --add-port=3002/tcp
sudo firewall-cmd --reload
```

## 쓰는 법

화면 안의 **사용자 가이드**(시작 화면의 책 아이콘, 분석 화면 오른쪽 위)에 같은 내용이 예와 함께 있습니다.

### 시작 화면 (`http://<서버 주소>:3002`)

로고 아래 검색창 하나로 시작합니다.

| 버튼 | 하는 일 |
|---|---|
| Job ID 입력칸 | 지난 실행 기록에서 job_id(또는 파일 이름 일부)를 찾습니다. ↑ · ↓로 고르고 Enter를 누르면 저장된 결과를 다시 계산하지 않고 엽니다. 숫자 Job ID면 목록 끝의 **DB에서 가져와 분석**으로 DB에서 데이터를 읽어 기본 설정으로 바로 실행합니다(기록이 없으면 이것이 기본). DB에 데이터가 없으면 raw.csv를 올리라고 안내합니다 |
| 왼쪽 CSV 칩 | raw.csv를 올립니다. 다 올라가면 분석 화면(설정)으로 넘어가니 설정을 확인하고 Run을 누릅니다 |
| 시계 아이콘 | 최근 실행 8개 (모든 사용자의 실행) |
| 책 아이콘 | 사용자 가이드 |
| 오른쪽 위 달 · 해 아이콘 | 밝은 · 어두운 화면 바꾸기 (분석 화면 · 가이드에도 있음, 브라우저에 기억) |

분석 화면 왼쪽 위의 **UNIT_COMMONALITY**를 누르거나 브라우저의 뒤로 가기로 시작 화면에 돌아옵니다.

### 분석 화면

1. **데이터 · 설정 · Run**: 맨 위 한 줄(시작 화면 검색창과 같은 모양)에 Job ID를 넣거나, 왼쪽 **csv**를 눌러 raw.csv를 붙입니다. 붙인 파일이 있으면 그 파일로, 없으면 Job ID로 DB에서 가져와 실행합니다. 붙인 파일은 ✕로 빼고, History에서 지난 실행을 열면 그 실행의 파일이 붙습니다(DB에서 가져온 데이터도 `job_<Job ID>.csv`로 남아 설정만 바꿔 다시 돌릴 때 DB에 다시 묻지 않습니다). 계산하는 동안은 칩 캐릭터가 걷는 로딩 장면과 단계 · 걸린 시간이 나옵니다. `MIN_N`(조합에 필요한 최소 웨이퍼 수), `MAX_DEPTH`(조합에 묶을 최대 Order 수, "제한 없음" 가능)를 정하고 **Run**을 누릅니다. 평소 바꾸지 않는 설정은 **고급 설정**에 있습니다. 여러 사람이 동시에 눌러도 함께 돕니다(기본 4개까지, 넘으면 먼저 누른 순서대로 기다림). 같은 파일 · 같은 설정으로 이미 돌린 기록이 있으면 다시 계산하지 않고 그 결과를 엽니다.
   - 결과가 나오면 설정 카드는 "job 2281935 · MIN_N 4 · MAX_DEPTH 5 · [설정 바꾸기]" 한 줄로 접혀 결과가 화면 위로 옵니다.
   - 연 결과가 없을 때는 설정 카드 아래에 **최근 실행** 10개가 최신순 표(History와 같은 칸)로 나와 바로 열 수 있습니다.
2. **결론**: 결과 맨 위에 1위를 한 문장으로 보여 줍니다(예: "웨이퍼 356장 중 bad 30.9% (예상 15.0%) → 예상보다 56장 더 bad"). **복사**를 누르면 job_id를 붙인 문장이 복사되어 회의록 · 메신저에 바로 붙여 넣을 수 있습니다.
3. **History**(실행 기록): 오른쪽 위 **시계 아이콘**을 누르면 오른쪽에서 서랍으로 열립니다. 돌린 판정이 모두 남습니다(실행 시각 · job_id · analysis_date · 파일 · 설정 · 결과). 실행 중인 판정이 있으면 시계 아이콘에 점이 표시됩니다.
   - 줄을 누르면 저장된 결과를 다시 계산 없이 엽니다. 설정 칸도 그 실행의 설정으로 바뀝니다. 서버를 다시 켜도 기록은 남습니다.
   - **삭제**를 누르면 목록에서 바로 빠지고 화면 아래에 **되돌리기**가 6초 동안 뜹니다. 그 사이 누르지 않으면 서버에서 지워집니다. 돌고 있는 실행은 "멈추고 지울까요?"를 한 번 묻습니다.
   - 로그인이 없어서 모든 사용자가 같은 목록을 봅니다. 주소창 끝의 `#run=<실행 id>`까지 복사해 보내면 받은 사람도 같은 결과를 엽니다.
4. **Funnel**(모든 STEP의 조합): 세로축은 **종합 / y_value 평균 / y_value 로그 / bad 비율** 중에서 고릅니다. y_value 로그는 조합마다 y_value의 기하평균을 로그 눈금으로 그려, 한쪽으로 치우친 데이터에서도 위아래가 대칭에 가깝게 보이는 비교용 축입니다(y_value가 0 이하인 웨이퍼가 있으면 꺼짐). **띠 전체**는 가운데 선을 기준으로 위아래를 같은 폭으로 잡아 경계선 양 끝이 모두 보이고, **점 위주**는 점이 모인 곳을 크게 보여 줍니다(고른 것은 브라우저에 기억).
   - 빈 곳에서 **끌면** 상자 안의 순위가 모두 골라집니다. Ctrl · ⌘ · Shift를 누르고 끌거나 점을 누르면 지금 고른 것에 더합니다. 빈 곳을 누르면 고른 것이 풀립니다.
   - 번호 없는 빨간 점 중 웨이퍼가 같아 어느 순위에 묶인 대상은 누르면 그 대상의 상세를 바로 봅니다.
   - 기준선 밖 점은 **원인 후보**(진한 빨강)와 **따라 올라온 점**(속 빈 원)으로 나눠 그립니다. 따라 올라온 점은 엔진이 구분한 상속(원인 경로에 Order를 더 붙인 경로) · 하위 기인(원인 경로의 일부만 쓴 경로)이고, 범례에서 **[흐리게 | 숨기기 | 그대로]**를 고릅니다(브라우저에 기억, 상세의 경로 비교에도 같이 적용). 점에 마우스를 올리면 기대는 원인 경로가 나옵니다. 점 크기는 모두 같고, 순위 대표는 번호로 구분합니다. 이번 버전 전에 계산한 기록은 다시 Run해야 나뉩니다.
5. **Ranking**(혐의 대상 순위표): 줄을 누르면 그 순위 하나, **Ctrl · ⌘+클릭**은 더하거나 빼기, **Shift+클릭**은 범위로 고릅니다. 고른 줄은 funnel에서 원으로 표시됩니다. 경로는 "O1:유닛" 덩어리 사이에서만 줄을 바꿉니다.
   - **+n 같은 웨이퍼**: 웨이퍼가 90% 이상 같아 이 줄에 묶인 대상이 있으면 경로 아래에 붙습니다. 누르면 묶인 대상이 아래 줄(↳ · 겹침 · N · Bad % · Excess bad · Certainty)로 펼쳐지고, 그 줄을 누르면 그 대상의 상세를 봅니다.
   - 설명의 "같은 웨이퍼 · 다른 Order: …"는 같은 STEP에서 웨이퍼가 똑같이 나뉘는 다른 Order로 쓴 경로입니다.
   - 열 이름 옆 **ⓘ**에 마우스를 올리면 뜻과 예시가 나옵니다(Certainty, Excess bad, Exp. bad % 등).
   - **CSV**로 순위표 전체를 내려받습니다(엑셀에서 한글이 깨지지 않게 저장).
6. **고른 대상 비교**(비교 띠): 순위를 2개 이상 고르면 funnel · 순위표 아래에 생깁니다. 한 줄 = 대상 하나(순위 순, 묶인 대상 · 다른 STEP 탓 의심 대상은 그 순위 아래 들여 쓴 줄).
   - **빨간 점** = 이 경로의 bad 비율, **회색 점** = 같은 Order를 다른 Unit으로 지난 웨이퍼의 bad 비율, 모든 줄이 같은 눈금. 비율은 bad 웨이퍼 수 ÷ 웨이퍼 수(조합별 비율의 평균이 아님). good_bad가 없으면 y_value 평균.
   - 칸: 순위 · STEP / Path · 띠 · 이 경로 · 다른 Unit · 웨이퍼 수 · 웨이퍼 겹침. 숫자 칸은 오른쪽 끝을 맞춥니다.
   - 위쪽 순위와 웨이퍼가 50% 이상 겹치면 "웨이퍼 겹침" 칸에 "1위와 62% 겹침"이 붙습니다.
   - 줄을 누르면(또는 ↑ · ↓) 아래 상세가 그 대상으로 바뀌고, 마우스를 올리면 funnel에서 그 점이 강조됩니다.
7. **상세**: 지금 보는 대상 하나를 크기를 고정한 2 × 2로 보여 줍니다. 하나만 골랐으면 ◀ ▶가 순위를, 여러 개면 고른 대상을 차례로 넘기고("고른 대상 2 / 5"), ✕는 그 순위를 고른 것에서 뺍니다. 묶인 대상이 있으면 제목 아래 **묶음 버튼**(예: [step1000 · 대표] [step1002 · 겹침 97%] [다른 STEP 의심 · …])으로 바꿔 봅니다.
   - **Order × Unit**: 칸 = 그 Order에서 그 Unit을 지난 웨이퍼 전체의 bad 비율 · 웨이퍼 수(다른 Order 선택과 무관). 칸을 눌러 경로를 바꾸면 "탐색 중 (판정 아님)"이 붙고, **원래 경로로**로 돌아갑니다. Unit이 많으면 칸 안에서 스크롤됩니다.
   - **웨이퍼 산점도**: 가로 = 고른 Order 중 마지막 Order의 tkin_time, 세로 = y_value. **선택 경로 강조** / **조합별 색**, **점 크기** 막대(처음 4.5, 대상을 바꿔도 그대로, 브라우저에 기억). 점에 마우스를 올리면 그 웨이퍼의 root_lot_id · wafer_id · 경로 · 시각 · y_value · good/bad가 나오고, **CSV**로 지금 대상의 웨이퍼 목록(같은 Order를 지난 웨이퍼 전체, 선택 경로 여부 포함)을 내려받습니다. 이번 버전 전에 저장한 실행은 웨이퍼 번호가 없어 다시 실행해야 번호가 나옵니다.
   - **경로 비교**: 지금 경로(빨간 점 + 고리)를 다른 경로와 같은 funnel에 놓고 봅니다.
     - 범위 **[STEP 전체 | 같은 Order]**: STEP 전체(기본)는 이 STEP에서 계산한 모든 조합을 위쪽 funnel과 같은 눈금으로(웨이퍼 수는 로그 눈금) 찍고, 같은 Order는 고른 Order들을 다른 Unit으로 지난 조합만 찍습니다.
     - 세로축 **[종합 | y_value 평균 | bad 비율 | 초과 bad]**: 종합이 기본입니다. 초과 bad(good_bad가 없으면 N × ΔValue)는 순위 기준이라 지금 경로가 그 묶음의 맨 위에 옵니다. 종합에서는 웨이퍼가 적은 경로가 띠가 넓어 더 위에 찍힐 수 있습니다.
     - 그림 위 한 줄: "지금 경로: 이 STEP 조합 35개 중 Certainty 1위 · 초과 bad 1위"처럼 비교 범위 안에서 몇 번째인지 보여 줍니다. 칸을 눌러 경로를 바꾸면 "지금 선택(탐색 중)"으로 바뀝니다.
     - STEP 전체 보기는 이번 버전부터 실행할 때 저장합니다. 그 전에 저장한 실행은 Run을 다시 눌러야 나오고, 같은 Order 보기는 그대로 됩니다.
   - **이 경로 vs 다른 Unit**: 고른 Order를 모두 지난 웨이퍼를 비교합니다. 예: 경로가 O1:A → O3:B면 O1:A → O3:C, O1:D → O3:B처럼 지난 웨이퍼가 "다른 Unit"입니다.
     - **합쳐 보기**(기본): 이 경로와 다른 Unit 웨이퍼 전체의 bad 비율 막대 · y_value 상자그림 · 웨이퍼 점.
     - **나눠 보기**: Order마다 이 경로의 Unit을 지났는지로 나눕니다. "다른 Unit"은 같은 Order에서 이 경로가 아닌 Unit입니다(차트 아래에 한 줄로 나옵니다). 예: O1:ETC101-A · O3:ETC301-A 30.9%, O1:ETC101-A · O3:다른 Unit 5.4%, O1:다른 Unit · O3:ETC301-A 6.2%, O1:다른 Unit · O3:다른 Unit 5.8%면 Unit 하나가 아니라 조합 탓입니다. Order가 2~3개면 맞음 · 다름 조합마다, 4개 이상이면 맞는 Order 수로 묶고, 묶음이 많으면 y_value 분포는 생략합니다. Order가 1개인 경로는 나눌 것이 없어 버튼이 꺼집니다.
   - **같은 웨이퍼로 n위에 묶인 대상**: 웨이퍼가 90% 이상 같아 한 줄로 묶인 대상이 있으면 상세 위쪽에 겹침 비율 · 한쪽에만 있는 웨이퍼의 bad와 함께 나란히 나옵니다. 대표(순위표에 올라오는 쪽)는 초과 bad가 큰 쪽이고, 같으면 계산에서 먼저 나온 쪽(대개 STEP 순서가 앞선 쪽)입니다. **보기**로 그 대상의 상세로 바꿉니다. "다른 STEP 탓 의심" 대상도 같은 자리에서 봅니다(순위표에 있으면 "n위로 더해 보기"로 두 순위를 골라 비교).

## 알아 둘 점

- **시간 · 메모리**: 479MB 가상 데이터(웨이퍼 1,130장, Order 3,784개)에서 판정 약 22초, 실행 중 최대 메모리 약 2.5GB였습니다. 300MB raw.csv면 비슷하거나 조금 적게 듭니다. 판정은 실행마다 새 프로세스에서 돌고, 끝나면 그 프로세스가 쓴 메모리를 모두 돌려줍니다. 동시에 4개가 돌면 최대 10GB쯤 쓸 수 있으니 서버 메모리가 적으면 `COMBI_WORKERS`를 줄이세요.
- **결과 보관**: 실행마다 `data/runs/<실행 id>/`에 `meta.json`(설정 · 상태 · job_id), `result.json`(요약 · funnel · 순위표), `state.pkl`(상세 계산용 웨이퍼 데이터)을 저장합니다. 479MB 데이터 기준 실행 하나에 약 28MB입니다. 화면에서 삭제하거나 폴더째 지우면 됩니다. 서버가 꺼질 때 돌던 실행은 "중단됨"으로 남습니다.
- **코드가 바뀐 뒤**: 판정 코드(`combi/`)가 바뀌면 같은 파일 · 같은 설정이어도 새로 계산합니다. 예전 기록은 그대로 열 수 있고 목록에 "이전 코드"가 붙습니다.
- **올린 파일**: `data/uploads/`에 남습니다. 실행 기록을 지워도 올린 파일은 남습니다(같은 파일로 다시 돌릴 수 있게). 필요 없으면 지워도 되고, 그 파일로 만든 기록은 계속 열리지만 다시 계산은 못 합니다. `data/`와 `raw.csv`는 git에 올라가지 않습니다(`.gitignore`).
- **Job ID로 가져오기**: 노트북에서 raw.csv를 만들던 방식 그대로입니다. 표에서 `job_id = <Job ID>`인 줄을 connectorx로 읽고, `step_seq` 끝의 `_숫자`로 `step_ord`를 만든 뒤 `data/uploads/`에 `job_<Job ID>.csv`로 저장하고 판정합니다. Job ID는 숫자만 받습니다. DB에 접속하지 못하면 약 30초 동안 다시 시도한 뒤 오류로 끝나고, 오류 문구에 비밀번호는 나오지 않습니다.
- **데이터 형식**: 노트북과 같습니다. 컬럼 `analysis_date, job_id, root_lot_id, lot_id, wafer_id, tkin_time, line_id, part_id, step_seq, step_desc, eqp_id, chamber_id, ppid, y_value, good_bad, step_ord`가 있어야 합니다.
- **판정 방식**: `main` 브랜치 노트북의 부록 C와 같습니다(5%를 Order 1개 · 2개 · 3개 · 4개 이상 묶음으로 나눈 Bonferroni 기준선, 퍼짐 보정, part별 맞춤, 중복 조합 · 넘을 수 없는 조합 빼기).
- **로고 글꼴**: Poppins ExtraBold(Google Fonts 공식 저장소 `google/fonts`, SIL Open Font License 1.1)를 `web/static/fonts/`에 함께 두어 인터넷 없는 서버에서도 같은 모양으로 나옵니다. 라이선스 전문은 `web/static/fonts/OFL.txt`입니다.

## 문제 해결

- **3002 포트가 이미 쓰인다는 오류**: `COMBI_PORT=3003 python -m web`처럼 다른 포트로 띄우거나, 떠 있는 서버를 `pkill -f "python -m web"`로 끕니다.
- **새 버전을 올린 뒤 화면이 깨짐**: 서버가 화면 파일을 매번 확인하게 해 두었지만, 그 전 버전을 쓰던 브라우저는 한 번 `Ctrl+F5`로 새로 고쳐야 할 수 있습니다.
- **실행 중 오류**: 화면과 실행 기록에 원인이 나옵니다. 컬럼 이름이나 y_value(숫자인지)를 확인하세요. 자세한 내용(traceback)은 `data/runs/<실행 id>/meta.json`의 `trace`에 있습니다.
- **"계산이 중간에 멈췄습니다"**: 서버를 다시 켰거나 메모리가 모자라 계산 프로세스가 강제로 끝난 경우입니다. Run을 다시 누르고, 자주 나오면 `COMBI_WORKERS`를 줄이세요.
- **브라우저**: Chrome · Edge 111 이상에서 쓰세요. 개발 중에는 Chromium 기반 브라우저로 확인했습니다.
