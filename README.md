# UNIT_COMMONALITY (웹)

설비 이력에서 bad를 끌어올린 설비 · 챔버 경로(공정 유닛 조합)를 찾아, funnel 차트와 혐의 대상 순위표로 보여 주는 웹 화면입니다. 사내 서버에 띄우고 브라우저로 접속해 씁니다(기본 포트 3002, 로그인 없음). 데이터는 **Job ID**로 DB에서 바로 가져옵니다. 엑셀의 **웨이퍼 값**(ROOT_LOT_ID · WAFER_ID · Y_VALUE · GOOD_BAD)을 붙여넣어 시작할 수도 있습니다(붙여넣은 웨이퍼의 설비 이력을 DB에서 가져와 분석하는 부분은 DB 조회 함수를 연결한 뒤에 켜집니다).

판정 계산은 `main` 브랜치의 `notebooks/real_data_funnel.ipynb`(커밋 `699e381`)와 같은 결과를 냅니다. 같은 데이터와 같은 설정이면 조합, z, 기준선, 판정, 혐의 대상 순위가 모두 같습니다.

## 구성

| 경로 | 내용 |
|---|---|
| `combi/` | 계산 엔진: CSV 읽기 · Value 치우침과 part 맞춤 · 조합 판정 · 혐의 대상 순위 · 화면에 보낼 값. `db.py`는 Job ID로 DB에서 데이터 가져오기 |
| `web/app.py` | 웹 서버: 실행(따로 프로세스에서 여러 개 동시에) · 실행 기록 · 결과 · 상세 · 비교 API |
| `web/worker.py` | 판정 한 번을 계산하는 프로세스: 결과를 `data/runs/<실행 id>/`에 저장 |
| `web/static/` | 화면 (HTML · CSS · JS, 외부 라이브러리나 인터넷 연결 없이 동작). `paste.js`는 웨이퍼 값 붙여넣기 창(표 · UD 산점도), `guide.html`은 화면 안의 사용자 가이드, `fonts/`는 로고 글꼴(Poppins ExtraBold · `OFL.txt` 라이선스) |
| `requirements.txt` | 설치할 패키지 (버전 고정) |
| `demo_raw.csv` | 시험용 가상 데이터 (설치 확인용, 아래 "시험해 보기") |

## 실행 가이드 (RHEL 9 · Python 3.12)

### 1. 코드 받기

git이 있으면:

```bash
git clone -b funnel-web --single-branch https://github.com/mikebbang/edu_claude.git funnel-web
```

서버가 GitHub에 접속할 수 없으면(폐쇄망) PC에서 아래 ZIP을 받아 서버로 옮긴 뒤 풉니다.

```bash
unzip edu_claude-funnel-web.zip && mv edu_claude-funnel-web funnel-web
```

ZIP 주소: `https://github.com/mikebbang/edu_claude/archive/refs/heads/funnel-web.zip`

### 2. 가상환경(venv) 만들고 패키지 설치

```bash
cd funnel-web
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

- `python3.12`가 없다는 오류가 나면 `python3 --version`으로 3.12인지 확인하고 `python3 -m venv .venv`를 씁니다.
- 사내 PyPI 미러를 쓰는 서버라면 평소 pip 설정 그대로 설치됩니다. DB 조회용 `connectorx` · `polars` · `pyarrow`도 함께 설치됩니다.
- 예전 버전을 쓰던 폴더라면 코드를 받은 뒤 `pip install -r requirements.txt`를 한 번 더 실행합니다.

### 2-1. DB 연결 (Job ID로 가져오기)

DB 접속 주소에는 비밀번호가 들어 있어서 코드나 GitHub(공개 저장소)에는 넣지 않습니다. 서버의 프로젝트 폴더에 `.env` 파일을 만들어 넣습니다(`.gitignore`에 있어 git에 올라가지 않음).

```bash
cat > .env <<'EOF'
COMBI_DB_URL=postgresql://<사용자>:<비밀번호>@<DB 주소>:5432/occas
EOF
chmod 600 .env
```

- 노트북에서 쓰던 `cx.read_sql("postgresql://…", …)`의 접속 주소를 그대로 넣으면 됩니다. 비밀번호에 `!` 같은 글자가 있어도 `.env`에는 그대로 씁니다.
- 읽는 표는 `occas.tmp_fab_ept_table_tg`입니다. 다른 표를 쓰려면 `.env`에 `COMBI_DB_TABLE=스키마.표이름`을 더합니다.
- 서버를 다시 켜야 적용됩니다. `.env`가 없으면 DB 기능(Job ID로 가져오기)만 꺼지고, 지난 실행 기록 보기와 웨이퍼 값 붙여넣기 창은 그대로 됩니다.

### 3. 서버 실행

```bash
python -m web
```

`Uvicorn running on http://0.0.0.0:3002`가 나오면 브라우저에서 `http://<서버 주소>:3002`로 접속합니다. 끄려면 `Ctrl+C`를 누릅니다.

### 4. 터미널을 닫아도 계속 띄우기

```bash
nohup .venv/bin/python -m web > web.log 2>&1 &
```

- 끌 때: `pkill -f "python -m web"`
- 로그 보기: `tail -f web.log` (접속 기록은 앞에 날짜 · 시간이 붙습니다. 예: `2026-10-07 07:55:31 | INFO: 10.222.56.228:61884 - "GET /api/runs HTTP/1.1" 200 OK`)

서버가 다시 켜질 때 자동으로 띄우려면 systemd 서비스로 등록합니다(관리자 권한 필요). `/etc/systemd/system/combi-web.service`:

```ini
[Unit]
Description=UNIT_COMMONALITY 웹
After=network.target

[Service]
User=<실행할 계정>
WorkingDirectory=/<설치 경로>/funnel-web
Environment=COMBI_WORKERS=4
ExecStart=/<설치 경로>/funnel-web/.venv/bin/python -m web
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now combi-web
```

### 5. 다른 PC에서 접속이 안 되면 (방화벽)

```bash
sudo firewall-cmd --permanent --add-port=3002/tcp
sudo firewall-cmd --reload
```

## 쓰는 법

화면 안의 **사용자 가이드**(시작 화면의 책 아이콘, 분석 화면 오른쪽 위)에 같은 내용이 예와 함께 있습니다.

### 시작 화면 (`http://<서버 주소>:3002`)

로고 아래 검색창 하나로 시작합니다.

| 버튼 | 하는 일 |
|---|---|
| Job ID 입력칸 | 지난 실행 기록에서 job_id(또는 파일 이름 일부)를 찾습니다. ↑ · ↓로 고르고 Enter를 누르면 저장된 결과를 다시 계산하지 않고 엽니다. 숫자 Job ID면 목록 끝의 **DB에서 가져와 분석**으로 DB에서 데이터를 읽어 기본 설정으로 바로 실행합니다(기록이 없으면 이것이 기본). DB에 데이터가 없으면 웨이퍼 값을 붙여넣으라고 안내합니다 |
| 왼쪽 붙여넣기 버튼 | **웨이퍼 값 붙여넣기** 창을 검색창 바로 아래에 펼칩니다 (다시 누르면 닫힘, 아래 "웨이퍼 값 붙여넣기") |
| 시계 아이콘 | 최근 실행 8개 (모든 사용자의 실행) |
| 책 아이콘 | 사용자 가이드 |
| 오른쪽 위 달 · 해 아이콘 | 밝은 · 어두운 화면 바꾸기 (분석 화면 · 가이드에도 있음, 브라우저에 기억) |

분석 화면 왼쪽 위의 **UNIT_COMMONALITY**를 누르거나 브라우저의 뒤로 가기로 시작 화면에 돌아옵니다.

### 웨이퍼 값 붙여넣기

시작 화면 검색창 왼쪽 버튼을 누르면 검색창 바로 아래에 창이 펼쳐집니다(분석 화면은 데이터 줄 왼쪽 버튼 → 데이터 줄 아래). 창이 열려 있어도 Job ID는 그대로 입력할 수 있습니다. 엑셀에서 표를 복사해 창에서 **Ctrl+V** 합니다. 창의 아래 · 양옆 · 오른쪽 아래 모서리를 끌어 크기를 바꿉니다(두 번 누르면 처음 크기). 단추는 그림만 있고, 마우스를 올리면 설명이 나옵니다.

| 단추 | 하는 일 |
|---|---|
| 붙여넣기 (클립보드) | 클립보드의 표를 넣습니다. 사내 서버(http)에서는 브라우저가 막아서 "Ctrl+V를 누르세요"가 나오니 Ctrl+V를 누릅니다 |
| RESET (돌아가는 화살표) | UD로 바꾼 것이 있으면 그것만 지워 붙여넣은 GOOD_BAD로 되돌리고, 없으면 표를 비웁니다. 둘 다 알림의 **되돌리기**로 살립니다 |
| UD (산점도) | 표 옆 산점도를 켜고 끕니다 |
| ▶ | 분석 실행: 웨이퍼 목록(ROOT_LOT_ID · WAFER_ID · Y_VALUE · GOOD_BAD 네 개, GOOD_BAD는 UD 결과 포함)으로 설비 이력을 DB에서 가져와 분석합니다. 시간 · 범례용 열은 이 창에서만 씁니다. 시작 화면에만 있고, 분석 화면에서는 설정 카드의 **Run** 하나로 실행합니다(아래). **DB 조회 함수를 연결하기 전**이라 지금은 목록만 준비됩니다 |
| ✕ | 닫기 (창 안에서 Esc, 또는 여는 버튼을 다시 누름). 붙여넣은 표 · UD 표시 · 창 크기는 창을 닫거나 새로 고쳐도 이 브라우저에 남습니다 |

- **표 · 쓰는 열**: 왼쪽 표는 붙여넣은 열을 그대로 보여 줍니다. 그중 ROOT_LOT_ID · WAFER_ID · Y_VALUE · GOOD_BAD · 시간으로 쓸 열을 알아보고, 머리글 아랫줄에 쓰는 곳을 적습니다. 예: `value1 / Y_VALUE`, `value2 / Y 후보`, `EQP / 범례용`. 지금 Y로 그리는 열은 머리글 밑줄로 표시됩니다.
- **알아보는 법**: 열 이름 목록(별명) 없이 값 모양(숫자 · 실수 · 시각 · G/B · 되풀이 · 값 길이), DB 열 이름과 닮은 정도(예: `Y1_ROOT_LOT_ID` · `lot` → ROOT_LOT_ID, `wf` → WAFER_ID), lot + wafer 한 쌍이 줄마다 하나인지, 전에 고른 열 이름으로 찾습니다. 그래서 한글 열 이름(로트 · 웨이퍼 · 판정 · 투입시간), 처음 보는 이름, 열 이름이 없거나 순서가 섞인 표도 맞춥니다. 첫 줄이 열 이름인지도 값 모양으로 판단합니다(아래는 숫자 · 시각인데 첫 줄만 글자면 열 이름).
- **Y_VALUE**: 숫자 열이 여럿이어도 헷갈리지 않게 정해진 순서로 고릅니다: 전에 골라 둔 열 → 이름이 Y_VALUE · value처럼 분명한 열 중 왼쪽 첫째 → 왼쪽 첫 **실수** 열(소수점 있는 값) → 왼쪽 첫 숫자 열. 예: `lot · wafer · value1 · value2 · value3 · time` → value1, `LOT · WAFER · STEP_NO(정수) · THK(실수)` → THK.
- **바꾸기**: Y는 산점도 왼쪽 위의 **Y 고르기**에서 숫자 열 중 하나를 고르거나, 표에서 그 열의 머리글을 눌러 **Y_VALUE**를 고릅니다. 다른 역할도 머리글 메뉴에서 바꿉니다(그 역할을 맡던 열과 서로 바뀜). 고른 것은 열 이름으로 기억해 다음 붙여넣기부터 바로 씁니다(되돌리기 가능). Y를 바꾸면 UD 막대 · 선은 처음 위치로 돌아가고, 색 · 범례에서 뺀 묶음은 그대로입니다. 같은 메뉴의 **첫 줄 = 열 이름**으로 첫 줄을 열 이름으로 볼지 바꿉니다.
- **범례용 열**: 쓰는 열이 아닌 나머지 열은 UD 산점도의 **색**으로 나눠 봅니다.
  - 값이 30가지 이하인 열(EQP · PRODUCT 등)은 **묶음 색**입니다. 범례 항목을 누르면 그 묶음을 판정에서 빼거나(none, 남은 웨이퍼로 bad %를 다시 셈) 다시 넣습니다.
  - 실수 열(value2 등, 또는 값이 30가지 넘는 숫자 열)은 **진하기**입니다: 작을수록 옅게, 클수록 진하게(5~95% 범위, 밖은 끝 색). 범례는 색 막대와 양 끝 값입니다.
  - 값이 30가지 넘는 글자 열(메모 등)은 색으로 쓰지 않고 표에만 보입니다.
- **GOOD_BAD**: good · bad · g · b · OK · NG · PASS · FAIL · 1 · 0처럼 어떻게 적어도 **G · B · N**으로 바꿔 표에 보여 주고 그대로 넘깁니다(대소문자 무관, 빈칸은 N = 계산에서 뺌). 붙여넣은 글자는 칸에 마우스를 올리면 나옵니다. 뜻을 모르는 값(예: REJ · ACC)은 N으로 치고 표 아래에 "GOOD_BAD 모르는 값"이 뜹니다. 누르면 값마다 G · B · N을 정하는 메뉴가 열리고, 정한 뜻은 기억합니다.
- **표**: 모든 줄을 스크롤로 봅니다. 열 폭은 내용에 맞추고, 머리글 오른쪽 끝을 끌어 바꿉니다(두 번 누르면 다시 맞춤). 고칠 칸(숫자가 아닌 Y_VALUE, 빈 ROOT_LOT_ID · WAFER_ID, 읽지 못한 시간)은 빨갛게 표시되고 그 줄은 빠집니다. 표 아래 한 줄에 웨이퍼 수 · 중복 · bad/good/none 수 · UD로 바뀐 수 · 고칠 칸 수가 나옵니다.
- **중복**: 같은 ROOT_LOT_ID + WAFER_ID가 여러 줄이면 표 아래에서 합치는 법을 고릅니다. 시간 열이 있으면 처음 · 마지막 줄(기본 마지막), 없으면 min · avg · max(기본 avg, GOOD_BAD가 서로 다르면 B가 하나라도 있으면 B). 쓰지 않는 줄은 흐리게 나옵니다.
- **UD**: 붙여넣은 GOOD_BAD가 우선이고, 더 조정하고 싶을 때만 켭니다. 산점도의 가로 = 시간 열(없으면 붙여넣은 순서), 세로 = Y_VALUE입니다. 바꾼 결과는 표의 GOOD_BAD에 바로 들어갑니다(바뀐 칸은 바탕색). 표와 산점도 사이 막대를 끌어 폭을 바꿉니다(두 번 누르면 처음 폭).
  - 위 **빨간 막대**(또는 산점도의 점선을 끌어)로 나쁜 쪽에서 몇 %를 bad로 할지 정합니다. 막대 옆에 비율 · 기준값 · 장수가 나옵니다(예: `18.0% · Y ≥ 3.26 · 54장`). 처음 위치는 붙여넣은 bad 비율(없으면 10%)이고, 막대 왼쪽 **화살표**로 나쁜 쪽(클수록 · 작을수록)을 바꿉니다(마우스를 올리면 지금 상태가 나옴). 예: 화살표 ↑ · 30% → Y가 큰 쪽 30%가 bad, 나머지는 good.
  - **none 구간** 단추(빨강 · 파랑 두 줄 그림)를 켜면 파란 막대 · 선이 하나 더 생겨 good을 따로 정하고, 두 선 사이는 none이 됩니다. 예: bad 20% · good 50% → 가운데 30%는 none.
  - 산점도에서 **상자로 끌면** 고른 웨이퍼를 bad · good · none으로 직접 정합니다(점에 테두리, 위 ✕로 모두 지움).

### 분석 화면

1. **데이터 · 설정 · Run**: 맨 위 한 줄(시작 화면 검색창과 같은 모양)에 Job ID를 넣으면 DB에서 가져와 실행합니다(왼쪽 버튼은 웨이퍼 값 붙여넣기 창). 실행 단추는 **Run** 하나입니다: 붙여넣기 창이 열려 있고 웨이퍼가 있으면 그 웨이퍼로(Run 왼쪽에 "붙여넣은 웨이퍼 300장으로 실행"), 창을 닫으면 Job ID로 실행합니다. Job ID 칸에서 Enter는 늘 Job ID입니다. History에서 지난 실행을 열면 그 실행의 데이터가 붙어(✕로 뺌) 설정만 바꿔 다시 돌릴 수 있습니다(DB에서 가져온 데이터는 `job_<Job ID>.csv`로 남아 DB에 다시 묻지 않습니다). 계산하는 동안은 칩 캐릭터가 걷는 로딩 장면과 단계 · 걸린 시간이 나옵니다. `MIN_N`(조합에 필요한 최소 웨이퍼 수), `MAX_DEPTH`(조합에 묶을 최대 Order 수, 기본 3, "제한 없음" 가능)를 정하고 **Run**을 누릅니다. 평소 바꾸지 않는 설정은 **고급 설정**에 있습니다. 여러 사람이 동시에 눌러도 함께 돕니다(기본 4개까지, 넘으면 먼저 누른 순서대로 기다림). 같은 데이터 · 같은 설정으로 이미 돌린 기록이 있으면 다시 계산하지 않고 그 결과를 엽니다.
   - 결과가 나오면 설정 카드는 숨고, 데이터 · 설정은 결론 카드 아래 한 줄로 옮겨 결과가 화면 위로 옵니다. 그 줄의 **설정 바꾸기**를 누르면 설정 카드가 결론 위에 다시 펼쳐집니다.
   - 연 결과가 없을 때는 설정 카드 아래에 **최근 실행** 10개가 최신순 표(History와 같은 칸)로 나와 바로 열 수 있습니다.
2. **결론**: 결과 맨 위 카드 하나에 모았습니다.
   - 첫 두 줄: 1위 경로와 숫자(예: "356장 중 bad 30.9% (예상 15.0%) · 56장 더 bad · Certainty 2.57"), 끝에 2 · 3위를 짧게. 웨이퍼가 같아 1위 줄에 묶인 대상이 있으면 경로 옆 **+n 같은 웨이퍼**를 눌러 순위표에서 펼칩니다. **복사**를 누르면 job_id를 붙인 문장과 이 실행 링크가 복사되어 회의록 · 메신저에 바로 붙여 넣을 수 있습니다.
   - 아래 회색 한 줄: 파일 · 웨이퍼 수 · bad 비율 · 검사한 조합 → 기준선 밖 수 · 설정. 보정(Value 치우침 · part 맞춤 · 퍼짐)이나 확인할 점이 있으면 "보정 1개" · "확인할 점 2개" 칩이 붙습니다.
   - **자세히**: 실행(job_id · analysis_date · 실행 시각 · 걸린 시간), 데이터 세부(뺀 웨이퍼 · lot · STEP 수 · 가능한 조합), 보정 · 확인할 점(있을 때만), 판정 정보 표.
3. **History**(실행 기록): 오른쪽 위 **시계 아이콘**을 누르면 오른쪽에서 서랍으로 열립니다. 돌린 판정이 모두 남습니다(실행 시각 · job_id · analysis_date · 파일 · 설정 · 결과). 실행 중인 판정이 있으면 시계 아이콘에 점이 표시됩니다.
   - 줄을 누르면 저장된 결과를 다시 계산 없이 엽니다. 설정 칸도 그 실행의 설정으로 바뀝니다. 서버를 다시 켜도 기록은 남습니다.
   - **삭제**를 누르면 목록에서 바로 빠지고 화면 아래에 **되돌리기**가 6초 동안 뜹니다. 그 사이 누르지 않으면 서버에서 지워집니다. 돌고 있는 실행은 "멈추고 지울까요?"를 한 번 묻습니다.
   - 로그인이 없어서 모든 사용자가 같은 목록을 봅니다.
   - **링크로 보내기**: 주소에 지금 보는 화면이 담깁니다. 예: `#run=<실행 id>&r=1,3`(고른 순위), `&t=r3`(상세에 보는 대상), `&p=0:0,2:1`(칸으로 바꾼 경로). 주소창을 복사하거나 상세 머리의 링크 아이콘을 누르면 받은 사람도 같은 대상 · 경로를 봅니다. 1위 하나만 보고 있으면 `#run=<실행 id>`만 남습니다.
4. **Funnel**(모든 STEP의 경로): 세로축은 **[종합 | y_value | bad 비율]** 중에서 고릅니다. 종합(기본)은 판정에 쓰는 점수입니다. y_value · bad 비율은 **보정 축**으로, 그 신호 하나로만 판정한다면 어디쯤인지를 원래 단위로 그립니다. 종합처럼 경로마다 자기 기준(Order 수 · 퍼짐 반영) 대비 위치를 Order 1개 기준 띠에 맞추므로, 선 밖이면 그 신호만으로도 판정 밖입니다. Order 1개 경로는 y_value 평균 · bad 비율과 (거의) 같고, Order가 많은 경로는 기준이 엄해서 가운데 쪽으로 당겨 그립니다. good_bad가 없으면 종합이 곧 y_value만 본 것이라 세로축 버튼 없이 종합으로만 그립니다. 이번 버전 전에 계산한 기록은 두 버튼이 흐리게 나오고, 서버를 새 코드로 다시 켠 뒤 Run을 다시 누르면 됩니다. 세로축 버튼 옆 **⚙**(보기 설정)를 누르면 자주 안 바꾸는 설정이 한곳에 나옵니다: **보는 범위** [띠 전체 | 점 위주](띠 전체는 가운데 선을 기준으로 위아래를 같은 폭으로 잡아 기준선 양 끝이 모두 보이고, 점 위주는 점이 모인 곳을 크게), **따라 올라온 점** [흐리게 | 숨기기 | 그대로], **산점도 점 크기**. 고른 값은 브라우저에 기억합니다.
   - 점에 마우스를 올리면 **판정 근거**가 나옵니다: 둘 다 · y_value만 · bad만 · 두 신호를 합쳐서 넘음. 보정 축에서는 그 신호 하나만 보면 선 밖이지만 종합으로는 판정되지 않은 경로가 **테두리 있는 회색 점**으로 나옵니다(순위에 오르지 않음).
   - 빈 곳에서 **끌면** 상자 안의 점이 모두 골라집니다. 순위 점은 그 순위로, 순위가 없는 점(good path 등)은 "순위 밖" 줄로 고른 대상 비교에 들어가고, 상세는 그중 첫 대상을 보여 줍니다. 예: good path만 있는 곳을 끌면 good path 7개가 비교 띠에 나란히 나옵니다. Ctrl 또는 Shift를 누른 채 끌거나 점을 누르면 지금 고른 것에 더하고(순위 밖 점은 다시 누르면 빠짐), 빈 곳을 누르면 고른 것이 풀립니다.
   - 번호 없는 빨간 점 중 웨이퍼가 같아 어느 순위에 묶인 대상은 누르면 그 대상의 상세를 바로 봅니다.
   - 순위 · 묶음이 없는 점(파란 good path, 회색 "y_value만 보면 밖" 점, 어느 순위에도 묶이지 않은 점)을 누르면 고른 순위는 그대로 두고 그 경로를 상세에서 봅니다. 상세에는 "good path"처럼 그 점의 판정과 "순위 밖"이 나오고, 테두리가 점선입니다.
   - 범례는 지금 그림에 있는 것만 보여 줍니다. 예: "원인 후보 3개 (같은 웨이퍼로 묶으면 순위 2개) · 따라 올라온 점 10개 · good path 7개 · 기준선 안 16,729개". 원인 후보와 순위 수가 다르면 그 이유를 괄호에 적습니다. y_value · bad 비율 축에서는 "— 기준선 = y_value 하나로만 판정할 때"가 붙습니다.
   - 사용법은 Funnel 제목 옆 ⓘ에 마우스를 올리면 나옵니다.
   - 기준선 밖 점은 **원인 후보**(진한 빨강)와 **따라 올라온 점**(속 빈 원)으로 나눠 그립니다. 따라 올라온 점은 엔진이 구분한 상속(원인 경로에 Order를 더 붙인 경로) · 하위 기인(원인 경로의 일부만 쓴 경로)이고, ⚙에서 **[흐리게 | 숨기기 | 그대로]**를 고릅니다(브라우저에 기억, 상세의 경로 비교에도 같이 적용). 점에 마우스를 올리면 기대는 원인 경로가 나옵니다. 점 크기는 모두 같고, 순위 대표는 번호로 구분합니다. 이번 버전 전에 계산한 기록은 다시 Run해야 나뉩니다.
5. **Ranking**(혐의 대상 순위표): 줄을 누르면 그 순위 하나, **Ctrl+클릭**은 더하거나 빼기, **Shift+클릭**은 범위로 고릅니다. 고른 줄은 funnel에서 원으로 표시됩니다. 경로는 "O1:유닛" 덩어리 사이에서만 줄을 바꿉니다.
   - **+n 같은 웨이퍼**: 웨이퍼가 90% 이상 같아 이 줄에 묶인 대상이 있으면 경로 아래에 붙습니다. 누르면 묶인 대상이 아래 줄(↳ · 겹침 · N · Bad % · Excess bad · Certainty)로 펼쳐지고, 그 줄을 누르면 그 대상의 상세를 봅니다.
   - 설명의 "같은 웨이퍼 · 다른 Order: …"는 같은 STEP에서 웨이퍼가 똑같이 나뉘는 다른 Order로 쓴 경로입니다.
   - 처음 보는 말인 **Excess bad**(good_bad가 없으면 N × ΔValue)와 **Certainty**에는 ⓘ가 있고, 다른 열 이름도 마우스를 올리면 뜻과 예시가 나옵니다.
   - **CSV**로 순위표 전체를 내려받습니다(엑셀에서 한글이 깨지지 않게 저장).
6. **고른 대상 비교**(비교 띠): 순위를 2개 이상 고르면 funnel · 순위표 아래에 생깁니다. 한 줄 = 대상 하나(순위 순, 묶인 대상 · 다른 STEP 탓 의심 대상은 그 순위 아래 들여 쓴 줄).
   - **빨간 점** = 이 경로의 bad 비율, **회색 점** = 같은 Order를 다른 Unit으로 지난 웨이퍼의 bad 비율, 모든 줄이 같은 눈금. 비율은 bad 웨이퍼 수 ÷ 웨이퍼 수(조합별 비율의 평균이 아님). good_bad가 없으면 y_value 평균.
   - 칸: 순위 · STEP / Path · 띠 · 이 경로 · 다른 Unit · 웨이퍼 수 · 웨이퍼 겹침. 숫자 칸은 오른쪽 끝을 맞춥니다.
   - 위쪽 순위와 웨이퍼가 50% 이상 겹치면 "웨이퍼 겹침" 칸에 "1위와 62% 겹침"이 붙습니다.
   - 줄을 누르면(또는 ↑ · ↓) 아래 상세가 그 대상으로 바뀌고, 마우스를 올리면 funnel에서 그 점이 강조됩니다.
7. **상세**: 지금 보는 대상 하나를 크기를 고정한 2 × 2로 보여 줍니다. 위쪽은 두 줄입니다. 노트북처럼 상세가 첫 화면 아래에 있을 때 순위를 바꾸면 화면 아래에 "2위 상세 ↓" 단추가 잠깐 떠서, 누르면 상세로 내려갑니다.
   - 첫째 줄: 순위 · STEP과 경로 칩(예: [O1:ETC101-A ×] → [O3:ETC301-A ×], ×로 그 Order 빼기). 칸이나 칩으로 경로를 바꾸면 "탐색 중 (판정 아님)"과 **원래 경로로**가 나타납니다. 오른쪽 ◀ ▶(키보드 ← →도 같음)는 하나만 골랐으면 순위를, 여러 개면 고른 대상을 차례로 넘기고("고른 대상 2 / 5"), ✕는 그 순위를 고른 것에서 뺍니다.
   - 둘째 줄: 웨이퍼 수 · bad 비율(다른 Unit) · y_value 평균 · Certainty. 묶인 대상이 있으면 오른쪽 **묶음 버튼**(예: 같은 웨이퍼 [ex102000 · 대표] [ex103000 · 겹침 97%])으로 바꿔 보고, **비교표 ▸**로 묶인 대상 표를 펼칩니다.
   - **Order × Unit**: 칸 = 그 Order에서 그 Unit을 지난 웨이퍼 전체의 bad 비율 · 웨이퍼 수(다른 Order 선택과 무관). 칸을 눌러 경로를 바꾸면 위쪽에 "탐색 중 (판정 아님)"이 붙고, **원래 경로로**로 돌아갑니다. Unit이 많으면 칸 안에서 스크롤됩니다.
   - **웨이퍼 산점도**: 가로 = 고른 Order 중 마지막 Order의 tkin_time, 세로 = y_value. **선택 경로 강조** / **경로별 색**. 점 크기는 funnel의 ⚙에서 바꿉니다(처음 4.5, 대상을 바꿔도 그대로, 브라우저에 기억). 점에 마우스를 올리면 그 웨이퍼의 root_lot_id · wafer_id · 경로 · 시각 · y_value · good/bad가 나오고, 상세 머리의 **내려받기 아이콘**(링크 아이콘 옆)으로 지금 대상의 웨이퍼 목록(같은 Order를 지난 웨이퍼 전체, 선택 경로 여부 포함)을 내려받습니다. 이번 버전 전에 저장한 실행은 웨이퍼 번호가 없어 다시 실행해야 번호가 나옵니다.
   - **경로 비교**: 지금 경로(빨간 점 + 고리)를 다른 경로와 같은 funnel에 놓고 봅니다.
     - 범위 **[STEP 전체 | 같은 Order]**: STEP 전체(기본)는 이 STEP에서 계산한 모든 조합을 위쪽 funnel과 같은 눈금으로(웨이퍼 수는 로그 눈금) 찍고, 같은 Order는 고른 Order들을 다른 Unit으로 지난 조합만 찍습니다.
     - 세로축은 위 funnel에서 고른 축(종합 · y_value · bad 비율)을 따라갑니다(차트 위에 "세로축: 종합 점수 · 위 funnel과 같은 축"). **초과 bad로 보기**(good_bad가 없으면 N × ΔValue로 보기)를 체크하면 순위 기준으로 바뀌고, 이때는 지금 경로가 그 묶음의 맨 위에 옵니다. 종합에서는 웨이퍼가 적은 경로가 띠가 넓어 더 위에 찍힐 수 있습니다.
     - 그림 위 한 줄: "지금 경로: 이 STEP 경로 35개 중 Certainty 1위 · 초과 bad 1위"처럼 비교 범위 안에서 몇 번째인지 보여 줍니다. 칸을 눌러 경로를 바꾸면 "지금 선택(탐색 중)"으로 바뀝니다.
     - STEP 전체 보기는 이번 버전부터 실행할 때 저장합니다. 그 전에 저장한 실행은 Run을 다시 눌러야 나오고, 같은 Order 보기는 그대로 됩니다.
   - **이 경로 vs 다른 Unit**: 고른 Order를 모두 지난 웨이퍼를 비교합니다. 예: 경로가 O1:A → O3:B면 O1:A → O3:C, O1:D → O3:B처럼 지난 웨이퍼가 "다른 Unit"입니다.
     - **합쳐 보기**(기본): 이 경로와 다른 Unit 웨이퍼 전체의 bad 비율 막대 · y_value 상자그림 · 웨이퍼 점. 상자나 "y_value 분포"에 마우스를 올리면 상자 = 가운데 50% · 굵은 선 = 중앙값 · 가로선 = 5~95%라는 설명이 나옵니다.
     - **나눠 보기**: Order마다 이 경로의 Unit을 지났는지로 나눕니다. "다른 Unit"은 같은 Order에서 이 경로가 아닌 Unit입니다(차트 아래에 한 줄로 나옵니다). 예: O1:ETC101-A · O3:ETC301-A 30.9%, O1:ETC101-A · O3:다른 Unit 5.4%, O1:다른 Unit · O3:ETC301-A 6.2%, O1:다른 Unit · O3:다른 Unit 5.8%면 Unit 하나가 아니라 조합 탓입니다. Order가 2~3개면 맞음 · 다름 조합마다, 4개 이상이면 맞는 Order 수로 묶고, 묶음이 많으면 y_value 분포는 생략합니다. Order가 1개인 경로는 나눌 것이 없어 버튼이 꺼집니다.
   - **같은 웨이퍼로 n위에 묶인 대상**(비교표 ▸): 웨이퍼가 90% 이상 같아 한 줄로 묶인 대상을 겹침 비율 · 한쪽에만 있는 웨이퍼의 bad와 함께 나란히 봅니다. 처음에는 접혀 있고, 설명은 제목 옆 ⓘ에 있습니다. 대표(순위표에 올라오는 쪽)는 초과 bad가 큰 쪽이고, 같으면 계산에서 먼저 나온 쪽(대개 STEP 순서가 앞선 쪽)입니다. **보기**로 그 대상의 상세로 바꿉니다. "다른 STEP 탓 의심" 대상도 같은 자리에서 봅니다(순위표에 있으면 "n위로 더해 보기"로 두 순위를 골라 비교).

## 알아 둘 점

- **시간 · 메모리**: 479MB 가상 데이터(웨이퍼 1,130장, Order 3,784개)에서 판정 약 22초, 실행 중 최대 메모리 약 2.5GB였습니다. 300MB 데이터면 비슷하거나 조금 적게 듭니다. 판정은 실행마다 새 프로세스에서 돌고, 끝나면 그 프로세스가 쓴 메모리를 모두 돌려줍니다. 동시에 4개가 돌면 최대 10GB쯤 쓸 수 있으니 서버 메모리가 적으면 `COMBI_WORKERS`를 줄이세요.
- **결과 보관**: 실행마다 `data/runs/<실행 id>/`에 `meta.json`(설정 · 상태 · job_id), `result.json`(요약 · funnel · 순위표), `state.pkl`(상세 계산용 웨이퍼 데이터)을 저장합니다. 479MB 데이터 기준 실행 하나에 약 28MB입니다. 화면에서 삭제하거나 폴더째 지우면 됩니다. 서버가 꺼질 때 돌던 실행은 "중단됨"으로 남습니다.
- **코드가 바뀐 뒤**: 판정 코드(`combi/`)가 바뀌면 같은 데이터 · 같은 설정이어도 새로 계산합니다. 예전 기록은 그대로 열 수 있고 목록에 "이전 코드"가 붙습니다.
- **가져온 데이터**: DB에서 가져온 데이터는 `data/uploads/`에 남습니다. 실행 기록을 지워도 남습니다(설정만 바꿔 다시 돌릴 수 있게). 필요 없으면 지워도 되고, 그 데이터로 만든 기록은 계속 열리지만 다시 계산은 못 합니다. `data/`는 git에 올라가지 않습니다(`.gitignore`).
- **Job ID로 가져오기**: 노트북에서 데이터를 만들던 방식 그대로입니다. 표에서 `job_id = <Job ID>`인 줄을 connectorx로 읽고, `step_seq` 끝의 `_숫자`로 `step_ord`를 만든 뒤 `data/uploads/`에 `job_<Job ID>.csv`로 저장하고 판정합니다. Job ID는 숫자만 받습니다. DB에 접속하지 못하면 약 30초 동안 다시 시도한 뒤 오류로 끝나고, 오류 문구에 비밀번호는 나오지 않습니다.
- **데이터 형식**: 노트북과 같습니다. 컬럼 `analysis_date, job_id, root_lot_id, lot_id, wafer_id, tkin_time, line_id, part_id, step_seq, step_desc, eqp_id, chamber_id, ppid, y_value, good_bad, step_ord`가 있어야 합니다.
- **판정 방식**: `main` 브랜치 노트북의 부록 C와 같습니다(5%를 Order 1개 · 2개 · 3개 · 4개 이상 묶음으로 나눈 Bonferroni 기준선, 퍼짐 보정, part별 맞춤, 중복 조합 · 넘을 수 없는 조합 빼기).
- **로고 글꼴**: Poppins ExtraBold(Google Fonts 공식 저장소 `google/fonts`, SIL Open Font License 1.1)를 `web/static/fonts/`에 함께 두어 인터넷 없는 서버에서도 같은 모양으로 나옵니다. 라이선스 전문은 `web/static/fonts/OFL.txt`입니다.

DB 없이 계산 엔진만 확인합니다. 프로젝트 폴더에서 가상 환경을 켠 채로:

python -c "import combi; from combi.views import run_payload; print(run_payload(combi.run('demo_raw.csv'))['ranking'][0]['path'])"

몇 초 안에 1위 경로 `O1:ETC101-A → O3:ETC301-A`가 나오면 정상입니다(혐의 대상 2개).

## 문제 해결

- **3002 포트가 이미 쓰인다는 오류**: `COMBI_PORT=3003 python -m web`처럼 다른 포트로 띄우거나, 떠 있는 서버를 `pkill -f "python -m web"`로 끕니다.
- **새 버전을 올린 뒤 화면이 깨짐**: 서버가 화면 파일을 매번 확인하게 해 두었지만, 그 전 버전을 쓰던 브라우저는 한 번 `Ctrl+F5`로 새로 고쳐야 할 수 있습니다.
- **실행 중 오류**: 화면과 실행 기록에 원인이 나옵니다. 컬럼 이름이나 y_value(숫자인지)를 확인하세요. 자세한 내용(traceback)은 `data/runs/<실행 id>/meta.json`의 `trace`에 있습니다.
- **"계산이 중간에 멈췄습니다"**: 서버를 다시 켰거나 메모리가 모자라 계산 프로세스가 강제로 끝난 경우입니다. Run을 다시 누르고, 자주 나오면 `COMBI_WORKERS`를 줄이세요.
- **브라우저**: Chrome · Edge 111 이상에서 쓰세요. 개발 중에는 Chromium 기반 브라우저로 확인했습니다.
